# 每日市场追踪部署指南（当前版本）

## 1. 推荐方案：本地优先

适合你现在这种“固定一台服务器、优先稳定”的场景。

### 1.1 首次部署

```bash
./scripts/local.sh setup
./scripts/local.sh cron-install
```

### 1.2 验证

```bash
./scripts/local.sh run social
./scripts/local.sh report evening
```

## 2. 定时任务策略

本地 `cron` 会自动安装以下任务：
- 每 30 分钟：市场数据 + 热榜
- 每天 08:00：社交抓取 + 早报
- 每天 20:00：社交抓取 + 晚报

说明：
- 早晚报默认会做联网检索补充（Google News RSS）并用于“为什么会这样”的上下文解释。
- 可在 `config/config.yaml -> report.web_context` 控制是否启用与默认关键词。

查看状态：
```bash
./scripts/local.sh status
```

移除任务：
```bash
./scripts/local.sh cron-remove
```

## 3. 微信公众号服务说明

微信公众号抓取依赖 `wechat-article-exporter` 登录态，首次需要扫码。

可选 Docker 启动：
```bash
./run.sh start all
```

扫码地址：
- `http://127.0.0.1:3001`

登录成功后，将 `auth key` 写到：
- `config/config.yaml` 的 `wechat.auth_key`
或环境变量：
- `WECHAT_AUTH_KEY`

## 4. Twitter/Nitter 说明

如果你需要稳定抓 Twitter，建议使用自建 Nitter token。
token 文件路径（当前仓库）：
- `finradar/nitter/sessions.jsonl`

更新脚本：
```bash
./scripts/update-twitter-token.sh <auth_token> <ct0>
```

## 5. DeepSeek 配置

报告 AI 摘要使用 DeepSeek：
- `config/config.yaml`：
  - `ai.api_key`
  - `ai.model`（例如 `deepseek/deepseek-chat`）
  - `ai.api_base`（默认可留空）

也可用环境变量覆盖：
- `DEEPSEEK_API_KEY`
- `DEEPSEEK_MODEL`
- `DEEPSEEK_API_BASE`

## 6. 可选 Docker 全托管

如果你后续要迁移到其他服务器，可改用 Docker 模式：

```bash
./run.sh build
./run.sh start all
```

## 7. 跨会话续做（开发）

如果是多人/多会话协作，建议每次改动后记录 checkpoint：

```bash
./scripts/dev_checkpoint.sh "本次改动目标" "下一步计划"
# 或
./scripts/local.sh checkpoint "本次改动目标" "下一步计划"
```

会写入 `docs/SESSION_CHECKPOINT.md`，新会话可直接读取恢复上下文。

仅主服务（不拉起社交源容器）：
```bash
./run.sh start all --no-sources
```
