# finradar 项目体检与改造报告（2026-02-09）

## 1. 体检结论

当前项目是一个“热点新闻 + 金融市场 + 社交媒体”的综合抓取与报告系统，主链路可分为：
- 抓取：`python -m finradar --mode news|market|social|all`
- 落盘：`output/market`、`output/news`
- 报告：`scripts/generate_report.py`

你关心的 3 个问题结论如下：

1. Docker 是否必须  
不是必须。你的场景更适合“本地优先 + Docker 可选”。

2. Twitter 是否支持热门讨论  
已改造为主链路内支持“关注账号 + 关键词热门讨论”。

3. 微信公众号是否可拿热门与正文  
已改造为主链路内支持“关注公众号 + 热门文章 + 正文采集（可配置）”。
前提是微信服务有有效登录态（需扫码）。

## 2. 发现的主要问题（改造前）

- 报告脚本存在运行错误（`date_str` 变量未定义）
- 社交热门抓取代码存在，但没有接入主执行路径
- 多个脚本使用过时路径（`fin_module`）或硬编码环境路径
- `scripts/fetch.sh` 调用了不存在的 `daily_fetch.py`
- Docker 与文档存在多套入口，实际使用成本高

## 3. 已完成改造

### 3.1 抓取链路
- `finradar/market/tracker.py`
  - Twitter：合并“关注账号推文 + 热门关键词推文”
  - 微信：合并“关注公众号文章 + 热门文章”
  - 新增统计字段：
    - Twitter: `follow_tweets_count`, `trending_tweets_count`
    - WeChat: `follow_articles_count`, `hot_articles_count`
  - 新增标记字段：
    - 推文：`is_trending`
    - 文章：`is_hot`

### 3.2 报告链路
- `scripts/generate_report.py`
  - 修复运行错误
  - 固定 DeepSeek 路径，支持从配置/环境变量读取 `api_key/base/model`
  - 社交数据解析兼容两种结构（`data.xxx` 和平铺 `xxx`）
  - 微信正文输入增强（不再只依赖标题/摘要）
  - 热榜读取改为按早报/晚报 12 小时窗口筛选

### 3.3 运行入口与脚本
- 新增本地优先工具：`scripts/local.sh`
  - `setup` / `run` / `report` / `cron-install` / `cron-remove` / `status`
- `run.sh` 增加 `local` 子命令，支持直接走本地运行
- 修复脚本路径与可执行性：
  - `scripts/fetch.sh`
  - `scripts/update-twitter-token.sh`
  - `scripts/update-wechat-key.sh`
  - `scripts/quick_test_trending.sh`

### 3.4 Docker（可选）
- `docker/docker-compose-unified.yml`
  - 主服务 `finradar`
  - 可选 profile `social-sources`：
    - `nitter`
    - `nitter-redis`
    - `wechat-exporter`
  - 社交源地址默认改为容器内服务名（非 localhost）

## 4. 当前建议架构

- 推荐：本地运行主程序 + 可选 Docker 社交源  
  - 主流程稳定、日志直观、排障简单
  - 迁移时可再切到全 Docker

## 5. 已知限制

- 微信公众号抓取受平台生态约束，登录态失效后需要重新扫码
- Nitter 依赖 token，公共实例不稳定，建议自建或在 Docker profile 内使用
- 飞书/Notion 推送未在本次改造中接入（按你的要求后置）

## 6. 后续建议

1. 增加“推送层”独立模块（Feishu / Notion）
2. 给社交抓取加健康检查与告警（登录失效自动提示）
3. 给报告输出增加结构化 JSON（便于二次加工）
